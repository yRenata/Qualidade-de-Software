## 1.3 Problemas identificados

- Erros e bugs
- Trabalho dobrado
- Atrasos de entrega
- Insatisfação do cliente
- Falta de padronização

---

## 1.4 Impactos desses problemas

Explique quais são as consequências desses problemas para o sistema e para os usuários.

> Resposta: As consequências são: A presença de erros e bugs torna o sistema instável e deixa o usuário desconfiado. O retrabalho deixa o sistema bagunçado e lento, fazendo com que o usuário sofra com atrasos e problemas. Esses atrasos na entrega mantêm o software desatualizado, gerando frustração e fazendo o cliente procurar outras opções. Além disso, a insatisfação do cliente reduz o uso do sistema e gera dificuldades de manutenção, resultando em experiências negativas. Por fim, a falta de padronização dificulta a manutenibilidade, deixando o código e todo o ecossistema confuso.

## 1.5 A qualidade é responsabilidade de quem?

Explique se a qualidade deve ser responsabilidade de uma pessoa ou de toda a equipe.

> Resposta: A qualidade é responsabilidade de todos os que estão na equipe. Ela é como um catalisador garantindo que a equipe construa o produto certo, da maneira certa.

# 3. Práticas de QA Sugeridas

Sugira práticas que a startup pode adotar para melhorar a qualidade.

---

## 3.1 Lista de práticas

- Padronização de processos
- Testes contínuos
- Code review
- Feedback constante

---

## 3.2 Explicação das práticas

Explique brevemente cada prática sugerida.

### Prática 1: Padronização de processos
> Descrição: Definir regras e padrões para o desenvolvimento (código/design).

### Prática 2: Testes contínuos
> Descrição: Realizar testes frequentes no sistema para identificar e corrigir erros.

### Prática 3: Code review
> Descrição: Código revisado por outros profissionais para aperfeiçoamento.

### Prática 4: Feedback
> Descrição: Coleta de avaliações de usuários e da equipe para identificar falhas e melhorar o sistema continuamente.

A startup decidiu contratar novos profissionais. Crie anúncios de vagas.

> Mínimo: 2 vagas

---

## 4.1 Vaga 1 – [Analista de Teste]

### Descrição da vaga
> Profissional para atuar na análise crítica de requisitos e definição de estratégia de testes.

### Responsabilidades
- Planejar, criar e executar casos de teste
- Identificar, documentar e acompanhar bugs
- Validar requisitos funcionais e não funcionais

### Requisitos obrigatórios
- Conhecimento em testes manuais e automatizados
- Noções de lógica de programação
- Experiência com ferramentas de gerenciamento de testes

### Requisitos desejáveis
- Experiência com metodologias ágeis
- Noções de API e testes de integração
- Conhecimento em automação de testes

### Certificações desejáveis
- CTFL

---

## 4.2 Vaga 2 – [Desenvolvedor Back-end]

### Descrição da vaga
> Profissional responsável pelo desenvolvimento e manutenção, garantindo desempenho, segurança e escalabilidade do sistema.

### Responsabilidades
- Desenvolver e manter APIs e serviços
- Garantir segurança e performance do sistema
- Trabalhar com front-end e banco de dados

### Requisitos obrigatórios
- Conhecimento em Node.js
- Experiência com banco de dados
- Conhecimento em APIs REST

### Requisitos desejáveis
- Experiência com frameworks
- Conhecimento em versionamento com Git
- Noções de segurança da informação

### Certificações desejáveis
